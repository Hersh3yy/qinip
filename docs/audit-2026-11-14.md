1. Bad tags. The background analysis writes tags on any `Ok` result with no check that the BPM is real. A track shorter than about 3.4 seconds, or silent, gets `bpm: 0.0`, and `write_analysis_tags` writes `TBPM` "0" with no range check, although `parse_bpm` (`tags.rs:53`) only accepts 20 to 400 when reading. Silent audio also correlates equally with every key, so the first key wins and `TKEY` becomes "C". Sample packs are full of one-shots this short. `existing_text_is_set` then stops Qinip from ever correcting the tag, while rekordbox and other tools read the bad values. The manual path (`app.rs:1399`) already requires a BPM. Fix: write `TBPM` only inside the `parse_bpm` range, have `detect_key` return no key when the chroma is flat, and add a unit test with silent and one-second audio that asserts nothing is written.
2. Unsafe writes. `Tag::write_to_path` opens the file read/write and, when the tag has to grow, shifts the audio payload in place. There is no temp file and no rename. The write runs in a detached `thread::spawn` that nothing joins on exit. `reanalyze_track` and `poll_worker` can start a second analysis for a path already being analysed, so two writers can touch one file. The opt-in flag is read once per thread, so unticking it does not stop writes in flight. Quitting during a write, especially on a USB stick or network share, can leave duplicated or missing audio. Confidence: high that the write is not atomic and not awaited, medium that two writers actually collide. Fix: write a tagged copy beside the file and rename it over the original, from one serial writer thread that the app drains on exit and that skips paths already in flight.
3. Stale work. The worker's only API is `enqueue`, and `clear_playlist` and `remove_from_playlist` reset everything except its queue. Results for removed tracks are thrown away only after the full decode and the waveform. Clear a 500-track folder and load another: the new one waits behind 500 wasted decodes. Each analysis is its own OS thread holding a whole decoded track. Fix: a `WorkerJob::Clear` or a generation counter, path removal on Remove, and a small fixed analysis pool (2 to 4 threads).
4. Release secrets. A job-level `env:` maps `MACOS_CERT_P12` and `APPLE_API_KEY_P8` into every step of the macOS job, including `dtolnay/rust-toolchain@stable` (a moving branch reference) and `cargo build`, so every dependency's build script sees them too. `softprops/action-gh-release@v2` runs with `contents: write` pinned only to a tag, and `cut-release.yml` puts `${{ inputs.version }}` straight into `run:` text. Dormant while the secrets are not set; fix it before adding the paid Apple account. Fix: delete the job-level `env:` and keep the secrets in step-level env where they are needed, pin third-party actions to commit SHAs, and pass the version through `env:` as `"$VERSION"`.
5. Real-time free. At the gapless swap the callback does `*track_guard = Some(next)`, which drops the old `TrackBuffer` on the audio thread. When the file's sample rate differs from the device's (44.1 against 48 kHz), the resampled buffer belongs to that track alone, so the free is tens of MB at exactly the moment the swap must be seamless. Every output frame also does a `try_lock` and an `Arc` clone. Confidence: high that the free happens on the audio thread, medium that it is audible. Fix: read the track once per callback, and send replaced buffers back to the UI thread over a channel to be freed there.
6. Tests. `playback.rs` (682 lines) has no `#[test]`: nothing covers the gapless swap, the loop wrap, the seek clamp or `resample_interleaved`. `decode.rs` has none for zero-length or truncated files, and `worker.rs` none for its de-duplication and priority. `render_output_f32` takes plain shared state and `PlaybackEngine::silent()` builds it without a device, so render N frames across a queued swap and a loop end and assert continuity; add decode tests on a truncated fixture and a zero-byte file.

## Checked and fine

- Decode handles malformed and truncated MP3s without panicking: I/O errors end the decode, bad packets are skipped, an empty result is an error, and `catch_unwind` wraps it.
- BPM and key analysis are wrapped in `catch_unwind` and have no division by zero on silence.
- An unreadable existing tag is left alone, not overwritten.
- The release scripts use `set -euo pipefail` with quoted variables, and `release.sh` checks the version with a regex.
- No committed secrets and no text addressed to AI agents.
